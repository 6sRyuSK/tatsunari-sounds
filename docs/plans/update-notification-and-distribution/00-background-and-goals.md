# 0. 背景と動機

UA Connect / Waves Central 型の「常駐アプリが勝手に更新する」体験を明確に避け
たい。実際の不満として挙がっているのは 2 点:

1. アプリが常駐し、意図しないタイミングで動く。
2. 久しぶりにプラグインの更新を確認しようとすると、**先にパッケージマネージャ
   自身の更新が入る**。

したがって本設計の中心命題は「**通知と実行を分離し、パッケージマネージャ自身は
極力更新しない**」となる。

---

## 実装スコープ契約

### 対象

- エディタ起動中だけ行う latest 情報の取得と、更新がある行への受動表示。
- 明示操作で起動する TUI による取得、検証、配置、受領書更新。
- GitHub Actions で生成した不変成果物の R2 配信と、静的ポインタ JSON の更新。
- stable と dev の別 ID 共存、およびユーザー / 全ユーザーの 2 スコープ。

### 非対象

バックグラウンド常駐、自動ダウンロード、自動インストール、利用状況送信、DRM、
ライセンス管理、プラグイン固有スクリプト、カスタム配置先、オフラインキャッシュは
本計画に含めない。必要になった場合は既存要件への「追加」ではなく、設計不変条件を
再審査する別 ADR とする。

### 成功指標と計測方法

| 指標 | 合格条件 | 計測 |
|---|---|---|
| 通常時の DAW 負荷 | audio thread からネットワーク処理を呼ばない | thread sanitizer / コードレビュー |
| 通知頻度 | 同一端末で 24 時間に 1 回以下 | fake clock を使う単体試験 |
| 既定 TUI 操作 | 従来の latest stable 導入よりキー操作を増やさない | golden transcript |
| 障害分離 | 壊れた 1 行を除外し、他行を操作可能にする | malformed fixture |
| 配信復旧 | pointer の直前版への差し戻しだけで復旧できる | staging drill |

## 着手条件

1. ドメインと DNS 管理者が人間により決定済みである。
2. `/tatsunarisounds/updates/v1/` の fixture と公開鍵 ID がレビュー済みである。
3. 本番へのアップロード、DNS 変更、秘密鍵操作の承認者が指定されている。
4. 各実装 PR が本索引のどのセクションを満たすか明記されている。
